# iFay 体系演进路线图与工程里程碑

本文档汇总 iFay 开放标准体系的**五阶段架构演进路线**与**分批次工程交付里程碑**，帮助协议实现者、宿主（Host）厂商与开发者理解当前规范的落地边界、模块就绪度以及下一步演进方向。关于五阶段构想的完整论述，请参阅蓝图第 04 章[《路线图：5 个阶段》](../blueprint/04-路线图.md)。

> **体系总览**：`Fay = iFay + coFay`。其中 **iFay**（Individual Fay，个体化身）复刻特定自然人（**人类原型**，Human Prime）的意志、偏好与能力边界，其合规性由 **iFACTS** 验证；**coFay**（Collective Fay，集体化身）承载组织或公共角色的集体意志，其治理与合规性由独立的 **coFACTS** 套件定义。

---

## 一、五阶段架构演进总览

iFay 采用**渐进式采纳（Progressive Adoption）**策略：每一阶段都在前一阶段的身份、权限与安全基座之上增量扩展，旧阶段合法签发的授权与装配清单在新阶段保持兼容。

| 阶段 | 阶段名称 | 核心交互范式 | 关键协议与核心部件 | 典型能力边界 |
|------|----------|--------------|--------------------|--------------|
| **第一阶段** | **模拟人类操作** | 基于视觉/听觉感知与 UI 动作的现有软件协作 | `FayID`、`Faying Protocol/1.0`、凭证管理、第一人称追踪器、模拟操作、`Ego` 微型模型 | 在不改造存量软件的前提下，受控代持人类原型委托凭证并执行可审计 UI 操作 |
| **第二阶段** | **直接接管客户端** | 意图直达宿主（Host）驱动接口与双向数据隧道 | 新增 `CAP 1.0`（控制权限协议）、`DTP 1.0`（数据隧道协议）、`ICP 1.0`（交互内容协议）、设备驱动中枢、传感器、个人数据堆 | 绕过僵化前端界面，通过结构化控制指令、安全态势门禁与加密数据隧道直接驱动终端软硬件 |
| **第三阶段** | **虚拟世界（C/F/S 架构）** | 围绕 iFay 重构软件生态：客户端（Client）– iFay – 服务端（Server） | 新增 `SSP 1.0`（技能共享协议）、`Telepathy Protocol/1.0`（心电感应协议）、注册技能、对齐意识 | 服务端向 iFay 暴露经签名的结构化技能与语义契约，跨化身低延迟协同 |
| **第四阶段** | **iFay + coFay 全面拟人化** | 个体化身与集体化身在社会规则下的多主体协作 | 社会关系与社会权限、自我感知、自驱行为、内部技能、跨主权监护与人格延续、与 `coFay` 协同 | 支持从指令控制（`command`）、Ego 控制（`ego`）向高度信任场景下的自主控制（`autonomous`）平滑演进 |
| **第五阶段** | **劳动与价值分配变革** | 以社会贡献度量替代投机性注意力分配 | **公誉链（GMChain）** 与 **美誉值（MeriToken，计量单位 `μ`）** 生态衔接 | 记录经核验的社会贡献并支撑公共治理话语权 |

### 关于第五阶段公誉链（GMChain）与美誉值（MeriToken）的定性边界

为确保技术路线与治理立场严格一致，第五阶段遵循以下定性原则（具体机制与量化参数以 `Global-Merit-Chain` 权威规范为准）：

1. **非货币属性**：**公誉链（GMChain）** 不是金融交易市场；**美誉值（MeriToken，单位 `μ`）** 是不可套现、不可转让、无二级市场、不可与法币双向兑换的社会贡献度量，不具备货币或投机资产属性。
2. **衰减式冷启动引导（Decaying Bootstrap）**：为解决新参与主体的冷启动话语权问题，体系仅允许**严格单向、设有硬上限**地以法币换取一份初始信誉额度；该初始信誉与体系内所有信誉遵循同一时间衰减机制，若缺乏持续的真实社会贡献，必将随时间衰减并坍缩至基础底值——财富无法购买持久的话语权。

## 二、分批次工程交付里程碑（Wave 0 – Wave 3）

围绕第一阶段与第二阶段的率先落地，以及第三阶段核心协议的互操作定型，iFay 社区按四个工程批次推进规范冻结、参考实现与测试套件建设：

### Wave 0：治理基线、术语红线与规范冻结准备
- **统一术语与权威源边界**：确立 `人类原型`（Human Prime）与 `宿主`（Host，仅指终端设备或宿主应用）的严格区分，明确各子项目仓库的单一权威源职责，消除跨仓库规范重复定义。
- **版本与版次治理**：以 `Faying Protocol/1.0`（`2025-10-25` 版次）为标尺，确立协议线格式采用两段式 `MAJOR.MINOR` 版本号、规范文档按日期冻结编辑版次的演进纪律（详见[《版本管理与兼容性规范》](../specification/versioning.md)）。

### Wave 1：核心协议规范定稿与 `FayManifest` 装配标准
- **身份与配对基座**：完成 `FayID`（RFC 4648 小写无填充 Base32 规范标识、HKDF-SHA256 域分离派生、`gmcref_` 盲化映射与单亲派生树约束）与 `Faying Protocol/1.0`（`G0`–`G4` 五级授权等级、单调降级收敛、`G0` 紧急接管抢占）规范及跨实现测试向量。
- **客户端与交互协议群**：定稿 `CAP 1.0`（含 `D-1..D-7` 安全红线：未知操作默认 `critical` 并拒绝、`G0` 安全态指令、不可逆动作人工确认门禁）、`DTP 1.0`（RFC 8785 JCS 帧头 + AES-256-GCM 端到端加密载荷）、`ICP 1.0`（`.ctx` 结构化交互块与副作用显式同意）及 `Telepathy Protocol/1.0`。
- **声明式组装清单（`FayManifest`）**：在主仓库 `schema/faymanifest/` 发布机器可读 JSON Schema 与样例清单，支持仅声明业务部件并自动补全 7 项核心基础设施与默认 `ego_model`。

### Wave 2：本地人格保险箱（`Ego`）与端到端垂直切片（`FayGer`）
- **`Ego` 双层签名模型包**：交付离线优先的人格对齐模型包规范与保险箱校验机制——通过 `manifest.json`（RFC 8785 JCS + `ifay.ego.package-signing.v1` 域分离 Ed25519 签名）保护分片权重摘要，并强制要求 `fidelity_report` 仅保留标量评估指标、杜绝原始语料泄露。
- **`FayGer` 第一/二阶段可运行闭环**：打通从 `FayID` 派生、`Faying` 授权签发、`Ego` 模型包签名挂载，到 `CAP` 指令门禁、`DTP` 加密帧传输与防篡改哈希链审计日志的本地端到端运行闭环。

### Wave 3：官方开发套件（`@ifay/sdk`）与合规认证套件（`@ifay/ifacts`）
- **零外部依赖官方 SDK（`packages/ifay-sdk`，`@ifay/sdk` v0.1.0）**：在主仓库提供纯 Node.js 标准库实现的轻量级开发套件，涵盖 `FayID` 解析与密钥派生、`Faying 1.0` Mandate 签发/校验、`FayManifest` 构建与阶段判定、`CAP 1.0` 客户端安全评估器、`SSP 1.0` 技能描述符分离式 Ed25519 JWS（`SkillProof`）签名，以及 `Ego` 清单验签。
- **可运行合规测试套件（`packages/ifacts-harness`，`@ifay/ifacts` v0.1.0）**：
  - 严格执行 **L1（单组件合规）→ L2（跨协议接口向量合规）→ L3（端到端生命周期与审计链合规）** 渐进式门禁：前序层级任一检查未通过时，后续层级自动标记为 `blocked_by_previous_level`，杜绝跳级认证；
  - 明确划清 `iFACTS` 与 `coFACTS` 边界，对 `cofay_` 目标主体返回显式越界错误码；
  - 输出机器可读的 `ifacts-report/1.0` 报告，并自动评定宿主应用的 **iFay Ready** 认证等级（`None` / `Bronze` / `Silver` / `Gold`）；L4（第四阶段人格漂移与压力下的长期行为一致性）诚实标注为 `deferred_phase_4_behavioral`。

## 三、近期演进重点（Next Horizon）

1. **多语言 SDK 对齐**：以 `@ifay/sdk` 与各协议仓库的冻结测试向量（`vectors/`）为基准，扩展 Python 与 Rust 语言绑定，确保跨语言字节级 JCS 与签名互操作。
2. **宿主（Host）生态接入与 iFay Ready 认证推广**：支持桌面端、移动端与物联网设备厂商通过 `CAP 1.0`、`DTP 1.0` 与 `SSP 1.0` 接入，使用 `ifacts` CLI 自检并获取 Bronze / Silver / Gold 等级评定。
3. **第四阶段行为一致性基准（iFACTS L4）预研**：围绕长期离线运行下的人格稳定性、多模态情境边界以及 `iFay` 与 `coFay` 的协作治理接口开展 SEP（规范增强提案）讨论。
